# Commit Skill

변경사항을 분석해 컨벤션에 맞는 한국어 커밋 메시지를 제안하고, 사용자 승인 후 커밋한다.

## 절차

### 1단계: 변경사항 파악

다음 커맨드를 병렬로 실행한다.

```bash
git status
git diff HEAD          # staged + unstaged 전체 diff
git diff --cached      # staged만
git log --oneline -5   # 최근 커밋 스타일 참고
```

### 2단계: 변경사항 분류

diff 결과를 읽고 변경 목적별로 묶는다. 서로 다른 목적의 변경이 섞여 있다면 **여러 커밋으로 분리**하는 것이 낫다.

분류 기준:
- 기능 추가 / 기능 수정은 각각 별도 커밋
- 스타일(CSS, 디자인) 변경은 로직 변경과 분리
- 설정 파일 변경은 단독 커밋 권장
- 서로 밀접한 변경은 하나로 묶어도 됨

### 3단계: 커밋 메시지 작성

**형식**: `type: 한국어 요약` (요약은 50자 이내)

| type | 사용 시점 |
|------|-----------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 코드 개선 |
| `style` | CSS·디자인·포맷 변경 (로직 변화 없음) |
| `chore` | 빌드·설정·패키지 변경 |
| `docs` | 문서·주석 변경 |
| `test` | 테스트 추가·수정 |

**예시**:
- `feat: 다크 모드 토글 버튼 추가`
- `style: 레트로 CRT 터미널 테마 적용`
- `fix: API 키 미입력 시 오류 메시지 누락 수정`
- `chore: Vite 의존성 버전 업그레이드`

본문이 필요한 경우(이유나 컨텍스트가 비자명한 경우에만):
```
feat: 멀티 프로바이더 지원 추가

Anthropic/Google 중 선택 가능하도록 provider 선택 UI 추가.
환경변수로 기본 키를 설정하면 입력란 없이도 동작함.
```

### 4단계: 사용자에게 제안 표시

분석 결과를 아래 형식으로 보여준다.

```
📋 변경사항 분석

[파일 목록과 간략한 변경 내용]

💬 제안하는 커밋:

1. git add <파일들>
   feat: 예시 메시지

(복수 커밋이 있을 경우 번호 순서대로)

승인하시겠습니까? (전체 승인 / 수정 필요 / 취소)
```

### 5단계: 승인 후 커밋 실행

사용자가 승인하면 제안한 순서대로 커밋한다.

```bash
git add <해당 파일들>
git commit -m "type: 메시지"
```

수정 요청이 있으면 메시지만 조정하고 재확인 없이 바로 커밋해도 되는지 묻는다.

## 주의사항

- `.env`, 비밀키, 자격증명 파일은 커밋하지 않는다 — 발견 시 사용자에게 경고
- `git add .` 또는 `git add -A`는 사용하지 않는다 — 항상 파일을 명시적으로 지정
- 이미 staged된 파일이 있으면 그 내용을 우선 반영하되, unstaged 변경도 함께 안내
- `--no-verify` 플래그는 사용자가 명시적으로 요청하지 않는 한 사용 금지
